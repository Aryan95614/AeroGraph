# AeroGraph: Graph-Augmented Retrieval for Multi-Hop Causal Reasoning over Aviation Safety Reports

## Abstract

Aviation safety analysis requires reasoning over complex causal chains spanning
multiple incident reports — a task at which standard retrieval-augmented
generation (RAG) systems consistently underperform. We present AeroGraph, a
GraphRAG system that constructs a domain-specific knowledge graph from NASA
Aviation Safety Reporting System (ASRS) incident reports using LLM-based entity
and relation extraction guided by an aviation safety ontology. AeroGraph
combines vector similarity search over report chunks with graph-structural
retrieval via entity neighborhood expansion, fusing both signals through
Reciprocal Rank Fusion (RRF) to surface evidence that spans report boundaries.
We evaluate on a 50-query benchmark suite comprising single-hop factual,
multi-hop causal, and comparative questions, measuring faithfulness, answer
relevance, context precision, and causal chain accuracy. Our results show that
GraphRAG retrieval improves multi-hop causal reasoning accuracy over a
vector-only baseline while maintaining competitive single-hop performance. We
analyze failure modes, discuss the limitations of synthetic evaluation data, and
release the full pipeline — ingestion, extraction, graph construction, hybrid
retrieval, and evaluation — as an open-source toolkit for safety-critical domain
RAG research.

## Limitations

We identify several limitations that scope the claims made in this work:

**Data provenance.** When bulk ASRS download is unavailable, we fall back to
synthetic reports generated by Claude. While these reports follow ASRS structure
and use realistic aviation terminology, they lack the distributional
characteristics of real incident data — particularly the long-tail anomaly
types and correlated contributing factors that make real safety analysis
challenging. All results obtained on synthetic data should be understood as
demonstrating system architecture, not domain-specific performance claims.

**Evaluation circularity.** Our faithfulness and relevance metrics use Claude as
an LLM judge evaluating answers also generated by Claude. This circular
dependency inflates scores and masks failure modes that a human evaluator would
catch. We report these metrics for relative comparison (GraphRAG vs. baseline)
rather than as absolute quality measures. Human evaluation is needed to validate
the benchmark.

**Extraction quality.** Entity and relation extraction via LLM is imperfect.
We observe entity fragmentation (the same concept extracted as multiple
distinct nodes) and hallucinated relations (edges not supported by the source
text). The 0.85 dedup threshold mitigates but does not eliminate fragmentation.
Extraction errors compound in the graph, affecting downstream retrieval.

**Ontology coverage.** Our aviation safety ontology (9 node types, 7 edge types)
is intentionally simple. Real aviation safety analysis requires finer-grained
distinctions — aircraft systems vs. subsystems, regulatory vs. procedural
factors, temporal vs. causal ordering. Extending the ontology would improve
graph utility but increase extraction complexity and cost.

**Embedding model.** all-MiniLM-L6-v2 is a general-purpose embedding model.
Domain-specific fine-tuning on aviation text would likely improve vector
retrieval quality, particularly for technical terminology.

**No temporal reasoning.** The current graph encodes causal and co-occurrence
relationships but not temporal ordering. Two events that the graph connects
via PRECEDED_BY may not be in true temporal sequence. Adding temporal edges
would require date normalization and sequence inference beyond our current
extraction capabilities.
