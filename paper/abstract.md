# AeroGraph: Graph-Augmented Retrieval for Multi-Hop Causal Reasoning over Aviation Safety Reports

## Abstract

Aviation safety analysis requires reasoning over complex causal chains spanning
multiple incident reports — a task at which standard retrieval-augmented
generation (RAG) systems consistently underperform. We present AeroGraph, a
GraphRAG system that constructs a domain-specific knowledge graph from 2,000
real NASA Aviation Safety Reporting System (ASRS) incident reports using
LLM-based entity and relation extraction guided by an aviation safety ontology
(10 entity types, 8 edge types). The raw extracted graph contains 29,244
entities and 43,505 relations; after taxonomy-based entity resolution and
cleanup the evaluation graph contains 23,948 canonicalized entities and 48,479
relations. AeroGraph combines vector similarity search over report chunks
with graph-structural retrieval via 2-hop entity neighborhood expansion,
Personalized PageRank, and BM25, fusing signals through Reciprocal Rank Fusion
(RRF) to surface evidence that spans report boundaries. We evaluate on a
50-query benchmark comprising single-hop factual, multi-hop causal, and
comparative questions across six retrieval systems: a 4-way HippoRAG-style
hybrid, vector-only GraphRAG, sparse BM25, graph-only, PPR-only, and a
vector-only baseline. The hybrid system reaches 0.210 precision@10 and 0.685
faithfulness under a local Ollama judge, and wins 62% of pairwise blind
comparisons against the vector baseline. Under a stricter Claude-as-judge
rubric, absolute faithfulness scores drop by 0.2–0.4 across all systems — a
consistent judge disagreement we discuss explicitly rather than paper over.
We release the full pipeline — ingestion, extraction, graph construction,
community detection, hybrid retrieval, dual-judge evaluation — as an
open-source toolkit for safety-critical domain RAG research.

## Limitations

We identify several limitations that scope the claims made in this work:

**Data provenance.** Our corpus consists of 2,000 real NASA ASRS incident
reports sourced from the elihoole/asrs-aviation-reports HuggingFace dataset
(38,655 records). While these are genuine pilot/controller narratives, our
2,000-report sample may not capture the full distributional characteristics of
the 1.8M+ reports in the ASRS database — particularly rare anomaly types and
long-tail contributing factor combinations.

**LLM-as-judge variability.** We report scores from two independent judges:
a local Ollama model (`qwen2.5:7b`) and Claude Sonnet. Claude is consistently
stricter, scoring 0.2–0.4 lower on faithfulness across all systems. Rankings
between systems are largely preserved across judges, but absolute numbers
should be interpreted as relative rather than absolute quality measures. We
publish per-query scores from both judges for inspection.

**Evaluation circularity.** The same model family (Claude Sonnet) is used for
entity extraction, answer generation, and one of the two judges. We mitigate
this by running a second independent local judge, but residual circularity
may inflate scores under the Claude judge in particular.

**Reference answers.** Reference answers were generated by Claude Sonnet over
the full corpus and constitute LLM-generated references, not human
gold-standard annotations. Reference similarity scores should be interpreted
accordingly.

**Extraction quality.** Entity and relation extraction via LLM is imperfect.
We observe entity fragmentation (the same concept extracted as multiple
distinct nodes) and hallucinated relations (edges not supported by the source
text). Taxonomy-based normalization (HFACS, ICAO aircraft/airport codes,
flight phases) resolves structured entities but residual free-text
fragmentation remains.

**Ontology coverage.** Our aviation safety ontology (10 node types, 8 edge
types) is intentionally simple. Real aviation safety analysis requires
finer-grained distinctions — aircraft systems vs. subsystems, regulatory vs.
procedural factors. Extending the ontology would improve graph utility but
increase extraction complexity and cost.

**Embedding model.** all-MiniLM-L6-v2 is a general-purpose embedding model.
Domain-specific fine-tuning on aviation text would likely improve vector
retrieval quality, particularly for technical terminology.

**Temporal reasoning limitations.** While the graph includes TEMPORAL_SEQUENCE
edges extracted from report narratives, temporal ordering is inferred from
narrative structure rather than ground-truth timestamps. Two events connected
by a temporal edge reflect the report author's description order, which may
not perfectly capture the actual chronological sequence.
